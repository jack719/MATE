# MATE: Two-Stage Alloy Information Extraction

This repository contains the parsing code used to extract titanium-alloy samples, compositions, processing routes, and mechanical properties from paper text. The maintained workflow starts with Markdown papers that have already been produced by a document-conversion tool such as MinerU.

## What is included

The repository is intentionally limited to the executable parsing path:

- `parse_downloaded_papers.py` is the command-line entry point.
- `src/freeform_parsing.py` implements two-stage generation, code extraction, domain validation, retry feedback, and result flattening.
- `src/utils.py` handles model loading, file discovery, continuation files, CSV persistence, and parser dispatch.
- `src/logging.py` writes timestamped console and log-file messages.

The former guidance/outlines parsers, XML-table cleaner, data-analysis notebooks and modules, paper-download helpers, and generated bytecode have been removed because they are outside this parsing workflow.

## Execution flow

For each Markdown file, the entry point:

1. extracts the title, abstract, and body;
2. builds the prompt and truncates the paper when `--max_tokens_body` is set;
3. calls the free-form parser;
4. runs Stage 1 to identify alloy samples;
5. runs Stage 2 to extract composition, heat treatment, and mechanical properties;
6. executes the generated code in the validation runtime;
7. retries Stage 2 with validation diagnostics when needed;
8. merges the two stages and appends metadata;
9. writes a CSV plus an exception JSON file.

Only the `unconstrained` parser is exposed because it is the only active path in this repository.

## Installation

Use Python 3.10 or newer and install the dependencies:

```bash
pip install -r requirements.txt
```

A local Hugging Face causal language model and its tokenizer are required. The model must support `generate`, and the tokenizer must provide `encode` and `decode`; `apply_chat_template` is used when available.

## Input format

Place one or more `.md` files in an input directory. The parser expects ordinary Markdown and attempts to recognize the first level-one heading as the title and an `Abstract`/`摘要` section as the abstract. Files shorter than 100 characters and files whose names contain `no_results` are skipped.

## Quickstart

```bash
python parse_downloaded_papers.py \
  --modelpath /path/to/model \
  --downloaded_papers_dir /path/to/markdown_papers \
  --save_dir ./outputs
```

The default CLI values point to the original authors' machine paths, so pass explicit paths on a new machine. To continue an earlier run, use `--continue_csv_path latest`; parsed filenames and exceptions are stored in the save directory.

## Outputs

The save directory contains:

- `results_<parameters>.csv`: flattened extraction records;
- `exceptions_<parameters>.json`: files that failed during reading, generation, or JSON conversion;
- `parsed_files_<parameters>.txt`: filenames already attempted;
- `log_<parameters>.log`: timestamped execution log.

## Reproducibility notes

The parser uses sampling (`temperature=0.7`, `top_p=0.9`) in `src/freeform_parsing.py`. Record the model checkpoint, input-paper version, CLI arguments, and output directory with each experiment. The repository does not include papers or model weights.

## Uploading the cleaned version back to GitHub

The cleaned work is on the local branch `cleaned-parser`. Review the diff, commit it, and push it to a branch on your fork or to a repository where you have write access:

```bash
git diff --check
git status
git add -A
git commit -m "Focus repository on free-form paper parsing"
git push -u origin cleaned-parser
```

Then open GitHub and create a pull request from `cleaned-parser` into the target default branch. If `origin` points to the upstream repository and you do not have push permission, create a fork, replace the remote URL, and push there:

```bash
git remote set-url origin https://github.com/<your-account>/MATE.git
git push -u origin cleaned-parser
```

Do not commit model weights, paper collections, generated CSV files, logs, or local paths.
